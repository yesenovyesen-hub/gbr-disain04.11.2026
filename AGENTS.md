# Правила проекта SIDEQUEST

## Текущий проект
- Сайт: `index.html`, `styles.css`, `app.js`; Vite собирает статические файлы в `dist/`. Node.js используется для локального запуска и сборки.
- Регистрация по email использует Amazon Cognito в `eu-central-1`. Публичный ID клиента находится в `cognito-config.js`. Код подтверждается в Cognito; локального сервера регистрации и Gmail-пароля больше нет.
- Дизайн экрана регистрации и подтверждения переносится из Figma. Вход, телефонная регистрация и другие функции ещё не реализованы.

## Перед изменениями
- Изучить относящиеся к задаче файлы и действующие инструкции. Проверить Git, если команда доступна, и сохранить чужие изменения.
- Не менять архитектуру и не добавлять зависимости без необходимости. Изменять только относящиеся к задаче файлы.

## Figma и дизайнер
- Использовать подключённые инструменты Figma для предоставленного пользователем Frame. Сначала изучить структуру, снимок, размеры, цвета, шрифты, ресурсы, состояния и варианты экранов.
- Сравнивать макет с существующим кодом и вносить минимальные изменения. Если дизайнер изменил один элемент, обновлять только его реализацию.
- Не редактировать оригинальный Figma-файл дизайнера без отдельного запроса.
- Кратко сообщать о недостающих вариантах, состояниях, поведении, ресурсах или противоречиях в макете.

## Код и проверка
- Сохранять работающую логику, использовать семантический HTML, доступные подписи, клавиатурные состояния и адаптивную верстку без горизонтальной прокрутки.
- Запускать локально через `npm start`, собирать через `npm run build`. Не утверждать, что визуальное сравнение сделано, если страница не была открыта или снимок не был изучен.
- Для публичной регистрации страницы о данных и условиях должны содержать действительный контакт владельца.

## Безопасность и выпуск
- Не публиковать секреты и пользовательские данные, не копировать содержимое `.env.local` в чат или Git.
- Не делать force push, коммиты и деплой без явного поручения. Не удалять чужие изменения.
- Регистрация не равна работающему входу. До публикации объяснять текущие ограничения и возможную стоимость AWS.
- После существенных изменений кратко объяснять по-русски, что сделано, какие файлы изменены, что проверено и что осталось.
